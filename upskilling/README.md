# Learn to own software changes

Your first target is to make, test, debug, and explain a small change yourself. Then grow toward owning a feature, handling failures, and making decisions with other people. Relay supplies realistic examples as you need them.

**Start with [your first session](FIRST_SESSION.md).** It uses one TypeScript function and Node, with no database or running application required. Budget 30–45 minutes; stopping with a clear question is useful progress.

The default placement is foundations because you described yourself as a novice/junior. Use the short diagnostic in the first session to adjust it. Skip material by demonstrating its exit task, rather than by recognising its vocabulary.

Use three sessions a week as an optional starting rhythm: learn one idea; build or debug something small; revisit it without the previous solution and explain a changed case. Adjust to your available time. A stage can take multiple weeks; there is no deadline for earning a job title.

Keep your prediction, failed attempt, smallest fix, test output, and explanation in [a session note](templates/session.md). Ask for help with the exact error and what you tried. Documentation is allowed throughout. Record any hints or generated code so you can tell what you can do unaided.

The twelve existing Relay labs are later resources, with prerequisites in the roadmap. Start the full platform only when a lesson needs it. AI mapping, external connectors, and the 100,000-row crash rehearsal are depth after core feature ownership.

Your progress lives in [learner-progress.json](learner-progress.json). It starts unassessed. Build evidence in `evidence/` describes Relay; your own work belongs in `submissions/`. Browser checkmarks are reflections only. Senior responsibility also needs repeated work with other people, feedback, and operational consequences; this project can prepare you for that practice.
