# Learning sessions

The user's current goal is to learn from novice/junior toward independent feature ownership and later senior judgment. Read `README.md`, `learner-progress.json`, and the latest learner submission before choosing a task. Default to `FIRST_SESSION.md` when no learner evidence exists.

During tutoring, give one bounded task and wait for the learner's attempt. Use the hint ladder in `BUILD_PROMPT.md`; do not fill in starter exercises on the learner's behalf. If the user explicitly requests implementation or curriculum maintenance, perform it and label assistance accurately. User instructions take precedence.

Maintain stable material IDs and preserve existing learner progress. Add evidence only for observed learner work. Platform tests, curriculum-author checks, assistant explanations, and browser reflections never establish mastery. Keep senior-level responsibility unassessed until repeated work, tradeoffs, collaboration, and operational feedback have been observed.

Changes to the curriculum may include runnable examples and reference solutions. Keep references separate from learner starters, and verify the exercise harness without modifying the learner's attempt. Scope stays Relay and upskilling; do not expand the product while asked to teach.
